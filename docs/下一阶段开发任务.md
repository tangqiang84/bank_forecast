## 下一步优先级

### P0：匹配结果确认与异常闭环（已完成）

- 已增加匹配结果列表、候选依据和人工确认、拒绝接口。
- 已增加异常事项分派、备注、处理完成、关闭和操作日志接口。
- `suggested` 结果确认后才更新流水匹配状态和应收已收金额，拒绝不产生财务计账。
- 已增加重复运行幂等控制，避免同一流水重复生成匹配结果和重复计账。

验收结果：通过。用户可以查看候选依据并确认或拒绝匹配；异常按 `new -> in_progress -> resolved -> closed` 流转并记录操作日志；重复运行不会重复生成结果或重复计账。

已交付接口：

- `POST /api/v1/matching/results/{id}/reject`
- `GET /api/v1/matching/exceptions`
- `POST /api/v1/matching/exceptions/{id}/assign`
- `POST /api/v1/matching/exceptions/{id}/comment`
- `POST /api/v1/matching/exceptions/{id}/resolve`
- `POST /api/v1/matching/exceptions/{id}/close`
- `GET /api/v1/matching/exceptions/{id}/logs`

### P1：匹配准确性和导入质量

- [ ] 支持一笔流水对应多个应收节点的拆分匹配（需要新增匹配分配明细模型）。
- [ ] 支持多笔流水合并匹配一个应收节点（需要与拆分匹配统一计账模型）。
- [x] 客户名称归一化和可配置最短匹配长度，减少公司后缀、空格、标点导致的误匹配。
- [x] 合同 CSV 逐行预校验、错误行查询/CSV 下载、重复节点跳过和导入摘要。
- [x] 银行流水导入文件大小、行数、日期范围、金额小数位和金额上限校验。

验收标准：边界输入返回结构化错误，错误行可定位，重复导入不会产生重复业务数据。

本轮交付：导入任务返回 `success_rows`、`failed_rows`、`skipped_rows` 和 `error_details`；错误明细接口为 `GET /api/v1/imports/{jobId}/errors`，CSV 下载接口为 `GET /api/v1/imports/{jobId}/errors/download`。拆分/合并匹配未在本轮实现，不得用于生产计账。

### P1：财务对账和可追溯性

- [x] 增加合同应收、银行流水、匹配结果、异常事项的关联详情页。
- [x] 增加财务确认记录、确认人、确认时间和审计日志查询。
- [x] 增加按租户、合同、项目、日期、状态的筛选和分页。
- [x] 驾驶舱补齐应收总额、已收金额、逾期金额、异常数量等真实指标。

验收标准：每条匹配和异常都能追溯到原始流水、合同节点和操作人。

验收结果：通过。流水详情可查看账户、匹配结果和审计日志；合同详情可查看应收节点、关联流水和审计日志；匹配结果详情可查看候选依据、原始流水、异常和操作记录；异常详情可查看来源对象和处理日志。列表接口统一支持分页，查询按当前租户隔离；驾驶舱指标改为从应收、流水和异常表实时汇总。

已交付接口：

- `GET /api/v1/bank-transactions`：按账户、合同编号、项目编号、交易日期、匹配状态分页查询流水。
- `GET /api/v1/bank-transactions/{id}`：查询流水及其匹配、审计记录。
- `GET /api/v1/contracts`：按合同编号、项目编号、状态分页查询合同。
- `GET /api/v1/contracts/receivables`：按合同、项目、到期日期、状态分页查询应收计划。
- `GET /api/v1/contracts/{id}`：查询合同、应收节点、关联流水和审计记录。
- `GET /api/v1/matching/results`：按合同、项目、交易日期、匹配状态分页查询匹配结果。
- `GET /api/v1/matching/results/{id}`：查询匹配结果、原始流水、关联异常和审计记录。
- `GET /api/v1/matching/exceptions`：按合同、项目、日期、异常状态分页查询异常事项。
- `GET /api/v1/matching/exceptions/{id}`：查询异常来源和处理日志。
- `GET /api/v1/audit-logs`：按对象类型、对象 ID、操作类型分页查询审计日志。

分页接口统一返回 `items`、`page`、`page_size`、`total`，单页最大 100 条。
